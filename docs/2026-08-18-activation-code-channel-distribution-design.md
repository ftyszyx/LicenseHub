# 激活码设备归属与后续充值分销设计方案

## 1. 背景

LicenseHub 的终端用户不需要注册或登录。终端用户获得激活码后，直接在应用中提交激活码和设备 ID 完成授权。

分销者需要登录自己的用户后台，但终端用户不需要账号。管理员为分销者生成一批激活码，分销者将这些激活码交付给终端用户。终端用户第一次使用分销激活码绑定设备后，该设备归属于对应分销者；以后该设备发生付费充值，分销者按设置比例获得佣金。

本方案替代基于“终端用户注册 + 推广链接 + 邀请关系”的新增分销方式。已有历史订单、佣金、提现和退款调整数据继续保留。

## 2. 核心方案

核心模型为：

> 分销者用户 + 激活码批次 + 设备首次归因 + 后续充值分成

完整流程如下：

```text
管理员选择一个“分销者”类型的后台用户
  -> 直接为该分销者生成一批激活码
  -> 激活码生成时绑定分销者和批次
  -> 分销者登录自己的后台查看、导出激活码
  -> 终端用户使用其中一个激活码首次绑定设备
  -> 系统将该设备永久归因给激活码所属分销者
  -> 分销者在后台查看激活码使用情况和名下设备
  -> 终端用户以后购买充值码并充值到该设备
  -> 充值成功后按设备归属生成分销佣金
  -> 分销者在后台查看充值记录、佣金和结算状态
```

该模式下：

- 终端用户不需要注册或登录。
- 分销者是后台用户的一种类型，使用现有用户账号登录。
- 普通用户和分销者需要区分，只有“分销者”类型用户才能接收分销激活码批次并进入分销后台。
- 初次分配给分销者的激活码只负责建立设备归属，本身不产生佣金。
- 只有真实付费订单生成的充值码成功充值到归属设备后，才产生佣金。
- 分成基于设备归属，不依赖浏览器 Cookie、推广链接或终端用户账号。

## 3. 关键概念

### 3.1 分销者

分销者直接使用现有 `users` 表中的用户账号，不创建渠道表，也不创建另一套分销账号表。

项目已有 RBAC 角色体系，建议增加内置 `distributor` 角色，并在用户管理页面显示为用户类型“分销者”。通过现有 `user_roles` 关联用户与该角色，不在 `users` 表中重复增加渠道 ID。

管理员创建激活码批次时只能选择“分销者”类型用户，该用户就是这批激活码的所有者。分销者登录后只能查看自己名下的批次、激活码、设备、充值记录和佣金。

### 3.2 分销激活码

由管理员为指定分销用户批量生成的激活码。生成时直接写入：

- 分销用户 ID。
- 分销批次 ID。
- 分配时间。

尚未绑定设备的激活码可以由管理员收回或转移；已经绑定设备的激活码不能再转移给其他分销者。

### 3.3 设备归属

设备归属表示某个应用下的设备由哪位分销者带来，唯一范围为：

```text
app_id + device_id
```

终端用户第一次使用分销激活码绑定一个尚未归因的设备时，系统将激活码所属分销用户写入设备归属。以后该设备充值时，均以这个归属计算佣金。

设备归属不依赖初始激活码是否过期。初始授权到期后，设备继续充值仍归属于原分销者。

### 3.4 后续充值

当前系统的购买流程是付款成功后生成一张新的激活码。因此，本方案中的“设备充值”定义为：

1. 终端用户通过付费订单取得充值码。
2. 终端用户将充值码应用到一个已经存在的设备。
3. 系统成功增加该设备的有效期或可用次数。

只有完成第 3 步才算充值成功。仅创建订单、支付成功但尚未使用充值码时，不产生设备分销佣金。

## 4. 设备归因规则

### 4.1 首次归因原则

设备尚未归因，并且本次使用的激活码属于某个分销者时，才建立设备归属。

```text
设备无归属 + 分销激活码首次绑定成功
  -> 建立设备与分销者的永久归属
```

建立归属必须和设备绑定放在同一个数据库事务中，避免并发请求将同一设备归给不同用户。

### 4.2 首次归因优先，不允许抢占

设备已经归属于分销者 A 后：

- 再使用分销者 B 的激活码不能改变设备归属。
- 再使用平台直营激活码不能清空设备归属。
- 设备续费、初始激活码到期或更换充值码不能改变设备归属。
- 分销者不能通过后台主动认领已有设备。

该规则可以防止分销关系被后续激活码抢占。

### 4.3 老设备不自动补绑定

只有本次激活过程中首次创建的新设备，才能通过分销激活码建立分销者归属。

数据库中已经存在的设备，无论是否已有分销归属，后续使用分销激活码都不能建立或抢占新的归属。功能上线前的历史设备、上线后已由普通激活码创建的设备以及归属为空的已有设备，均不允许补绑定。

系统不提供老设备批量导入、管理员补绑定或通过充值行为追溯绑定的功能。判断条件必须以设备绑定事务中是否新建 `app_devices` 记录为准，不能仅根据 `distributor_user_id IS NULL` 判断。

### 4.4 设备更换

更换设备按一个全新的终端用户处理，新设备不能继承旧设备的分销归属，系统也不提供管理员归属迁移功能。

新设备首次激活时：

- 使用分销者激活码，则归属于该激活码对应的分销者。
- 使用普通激活码，则不建立分销归属。

旧设备的归属、充值记录和历史佣金保持不变，与新设备互不关联。

### 4.5 管理员修正

分销者不能修改设备归属。管理员可以在确有错误时修正或解除归属，但必须满足：

- 修正仅适用于已经建立过分销归属的设备，不能为已有且未归属的设备新增归属。
- 填写操作原因。
- 写入归属变更审计流水。
- 不重新计算或转移已经生成的历史佣金。
- 只影响变更完成后的新充值。

## 5. 佣金生成规则

### 5.1 生成条件

同时满足以下条件时，才生成一笔设备充值佣金：

- 分销总开关已开启。
- 设备归属分销开关已开启。
- 充值码来自已支付且未退款的真实订单。
- 充值码已经成功增加目标设备的有效期或可用次数。
- 目标设备存在有效的分销用户归属。
- 该订单尚未生成过任何佣金。
- 分销用户状态正常，并且不是订单的登录购买人本人。

管理员手工生成的免费码、分销批次中的初始激活码、补偿码和测试码不产生充值佣金。

### 5.2 计算方式

佣金按充值订单实际支付金额计算：

```text
佣金金额 = floor(订单实付金额 x 佣金比例 / 10000)
```

佣金比例使用以下优先级：

```text
分销用户个人佣金比例
  > 系统默认佣金比例
```

订单完成设备充值时，需要保存佣金比例和佣金金额快照。以后修改默认比例或用户个人比例，不影响历史佣金。

系统默认比例继续使用管理员设置中的 `20%`，管理员可以修改，也可以为单个用户设置专属比例。

### 5.3 佣金产生时点

佣金在付费充值码成功应用到归属设备时产生，而不是在订单支付回调时产生。

原因是终端用户不登录，付款时系统还不知道充值码最终会用于哪台设备。只有充值成功后才能准确确认分销归属。

佣金观察期从充值成功时间开始计算，默认 `7 天`。观察期结束后，佣金从 `pending` 变为 `available`。

### 5.4 幂等规则

同一订单最多生成一笔佣金。数据库继续通过 `order_id` 单列唯一约束，防止重复回调、重复提交充值或并发请求生成多笔佣金。

旧推广链接停止产生新佣金。历史订单如果已经存在旧推广佣金，后续即使将对应激活码用于分销设备充值，也不再生成第二笔设备充值佣金。

如果充值码没有实际改变设备有效期或次数，本次请求不能生成佣金。

### 5.5 自购限制

如果订单由登录用户购买，并且购买用户就是设备所属分销者，不产生佣金。

游客购买没有可靠身份，系统无法完全判断是否为分销者本人。第一阶段保留订单、设备、IP 和时间等审计信息，后续可以增加异常频率和关联行为检查。

## 6. 退款和撤销规则

### 6.1 付款后尚未充值即退款

订单尚未将充值码应用到设备，因此没有佣金，只需要走现有订单退款和激活码作废流程。

### 6.2 充值成功后退款

充值订单已经产生佣金时，继续复用现有佣金退款链路：

- `pending` 或 `available`：取消尚未结算的佣金。
- `locked`：先撤销对应的待处理提现锁定，再取消佣金。
- `settled`：创建负向佣金调整，使用后续可用佣金抵扣。
- 存在未抵扣欠款时，禁止用户再次申请提现。

退款同时撤销充值码带来的授权增量，并保存充值前后的授权值，以便恢复有效期或次数。

### 6.3 设备归属不随充值退款变化

后续某一笔充值退款只处理该笔充值和佣金，不清除设备与分销者的归属关系。

如果初始分销激活存在欺诈或错误，需要解除设备归属，应由管理员执行归属修正，不能在普通订单退款中隐式修改。

## 7. 分销者后台

### 7.1 登录和菜单

分销者使用现有用户账号登录分销者后台，不进入管理员后台。前后端通过内置 `distributor` 角色识别用户类型和授权菜单。

当分销总开关关闭时，隐藏分销相关菜单，分销者首页仍正常显示。当开关开启时，只有“分销者”类型用户可以进入“分销中心”；尚未获得激活码的分销者显示空状态。

### 7.2 分销首页

展示：

- 已分配激活码总数。
- 未使用、已绑定、已作废数量。
- 已归属设备数量。
- 累计付费充值订单数和充值金额。
- 待确认、可提现、提现中和已结算佣金。

### 7.3 我的激活码

分销者只能查看分配给自己的激活码批次和激活码：

- 批次编号、应用、套餐和生成时间。
- 激活码、状态和分配时间。
- 绑定时间和绑定设备 ID。
- 查看和导出分配给自己的激活码，并可按未使用、已绑定、已作废等状态筛选。

批次生成并写入当前分销者用户 ID 后，该分销者即可查看和导出，不需要管理员再次标记交付。列表、详情和导出接口必须在服务端强制增加：

```text
distributor_user_id = 当前登录用户 ID
```

其他分销者的激活码以及尚未分配给任何分销者的激活码，对当前用户完全不可见，也不能通过修改请求参数查询或导出。

### 7.4 我的设备

展示由本人激活码建立归属的设备：

- 应用名称。
- 设备 ID。
- 来源激活码和批次。
- 首次绑定时间。
- 当前授权状态。
- 累计付费充值次数和充值金额。
- 最近充值时间。

不向分销者展示终端购买人的邮箱、IP、支付凭证、支付渠道原始报文或完整设备信息 JSON。

### 7.5 充值记录

展示本人名下设备的付费充值记录：

- 充值订单号。
- 应用和设备 ID。
- 充值套餐。
- 订单实付金额。
- 充值成功时间。
- 充值前后的有效期或可用次数。
- 佣金比例、佣金金额和佣金状态。
- 退款状态。

### 7.6 佣金和提现

继续复用现有用户分销中心中的佣金明细、提现申请、结算记录、负向调整和支付宝收款账户功能。

设备充值佣金和历史推广佣金需要通过来源类型区分，但可以合并计算可提现余额。

## 8. 管理员后台

### 8.1 分销批次管理

管理员创建批次时选择：

- “分销者”类型用户。
- 应用和商品套餐。
- 激活码数量。
- 激活码类型、有效期、总次数等现有参数。

创建后，系统一次性生成激活码，并自动写入分销者用户 ID 和批次 ID。管理员不需要再次执行绑定或标记交付；批次创建成功后，该分销者即可在自己的后台查看和导出。

### 8.2 设备归属管理

管理员可以：

- 按用户、应用、设备 ID、来源激活码和批次查询。
- 查看设备首次归因时间和充值统计。
- 修正或解除已存在的设备归属，但不能为已有且未归属的设备补绑定。
- 查看归属变更审计流水。

### 8.3 充值佣金管理

管理员可以按分销用户、设备 ID、订单号、佣金状态和充值时间查询，查看订单、充值记录、设备归属和佣金之间的完整关联。

### 8.4 用户管理

用户管理页面需要支持将用户类型设置为“分销者”。实现上复用现有 RBAC：

- 增加内置角色 `distributor`，中文显示“分销者”。
- 分销者角色拥有分销者首页、本人激活码、本人设备、本人充值记录、佣金和提现权限。
- 分销者角色不拥有用户管理、系统设置、全部订单或全部佣金等管理员权限。
- 管理员创建分销批次时，只能搜索和选择具有 `distributor` 角色的用户。
- 移除用户的分销者类型后，禁止继续分配新激活码，但保留其历史设备归属、充值和佣金数据。

继续使用现有用户个人佣金比例字段，不新增渠道级佣金设置。

## 9. 建议数据结构

程序已经上线，以下表结构变更必须通过新的 migration 实现，不能直接修改初始建表 SQL。

本方案不创建 `distribution_channels` 或类似渠道表。所有业务数据通过 `distributor_user_id` 直接外键关联 `users.id`：

```text
users.id
  -> distribution_code_batches.distributor_user_id
  -> reg_codes.distributor_user_id
  -> app_devices.distributor_user_id
  -> device_recharge_records.distributor_user_id
  -> distribution_commissions.user_id
```

同时通过 migration 创建内置 `distributor` 角色及其默认权限，作为后台中的“分销者”用户类型。

### 9.1 分销批次表 `distribution_code_batches`

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `batch_no` | 唯一批次编号 |
| `distributor_user_id` | 分销者用户 ID，外键关联 `users.id` |
| `app_id` | 应用 ID |
| `plan_id` | 商品套餐，可为空 |
| `quantity` | 生成数量 |
| `status` | 使用中、已关闭、已取消 |
| `created_by` | 创建管理员 ID |
| `created_at` / `updated_at` | 时间字段 |

批次只负责批量管理和追溯，不保存供货价、零售价或收款金额。

### 9.2 激活码表 `reg_codes` 扩展

| 字段 | 说明 |
| --- | --- |
| `distributor_user_id` | 所属分销者用户，可为空 |
| `distribution_batch_id` | 所属分销批次，可为空 |
| `allocated_at` | 分配时间，可为空 |

管理员普通生成、商城订单生成和历史激活码可以保持这些字段为空。

### 9.3 设备表 `app_devices` 扩展

| 字段 | 说明 |
| --- | --- |
| `distributor_user_id` | 当前归属的分销者用户，可为空 |
| `attribution_reg_code_id` | 首次建立归属的激活码 |
| `attributed_at` | 首次归因时间 |
| `attribution_updated_at` | 管理员最后修正时间，可为空 |

为 `distributor_user_id` 建立索引，便于用户后台按归属查询设备。

### 9.4 设备充值记录表 `device_recharge_records`

每次激活码成功增加设备授权时写入一条不可变记录：

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `app_device_id` | 目标设备 |
| `reg_code_id` | 本次使用的充值码 |
| `order_id` | 来源订单；免费码可为空 |
| `distributor_user_id` | 充值发生时归属的分销者用户快照，可为空 |
| `before_expire_time` / `after_expire_time` | 时间型授权变更，可为空 |
| `before_remaining` / `after_remaining` | 次数型授权变更，可为空 |
| `recharged_at` | 充值成功时间 |

对可产生佣金的付费充值，`order_id` 必须唯一，防止同一订单重复充值或重复产生佣金。

### 9.5 订单表 `orders` 扩展

建议增加：

| 字段 | 说明 |
| --- | --- |
| `distribution_device_id` | 产生分销归因的设备，可为空 |

订单现有的 `referrer_user_id`、佣金比例和佣金金额字段继续复用：历史订单表示旧推广接收人，新订单表示设备归属的分销者。`referral_code` 在新模式下保持为空。

充值成功后，在同一个事务中记录 `distribution_device_id`，将设备所属分销者及佣金比例、金额写入订单快照，并创建 `device_recharge` 来源佣金。

### 9.6 佣金表扩展

建议为 `distribution_commissions` 增加：

| 字段 | 说明 |
| --- | --- |
| `source_type` | 历史数据为 `referral`，新增佣金为 `device_recharge` |
| `app_device_id` | 来源设备，可为空 |
| `source_reg_code_id` | 实际完成充值的激活码，可为空 |

继续保留 `order_id` 单列唯一约束以及现有锁定、结算、取消和负向调整字段。

通过 migration 为历史佣金回填 `source_type = 'referral'`。功能切换后产生的佣金统一写入 `source_type = 'device_recharge'`。该字段只用于区分历史数据来源，不用于允许同一订单生成两笔佣金。

### 9.7 设备归属审计表 `device_distribution_events`

记录首次归因、管理员修正和解除：

- 设备 ID。
- 变更前后分销用户。
- 来源激活码。
- 操作类型。
- 操作管理员和原因。
- 操作时间。

## 10. 事务和并发要求

### 10.1 首次激活事务

首次使用分销激活码时，在同一事务内：

1. 锁定激活码。
2. 查询或创建并锁定应用设备。
3. 检查设备是否已有归属。
4. 只有设备由本事务首次创建时，才写入分销用户和来源激活码；已有设备保持原归属不变。
5. 更新设备授权和激活码状态。
6. 写入设备归属事件。

### 10.2 后续充值事务

付费充值码应用到设备时，在同一事务内：

1. 锁定充值码、订单和目标设备。
2. 校验订单已支付、未退款且充值码未被使用。
3. 保存充值前授权值。
4. 增加设备授权并写入充值记录。
5. 读取设备分销归属。
6. 满足条件且订单尚无佣金时，记录订单目标设备和分销者佣金快照，并创建 `device_recharge` 来源佣金。
7. 更新充值码状态。

锁顺序必须固定，避免与订单退款和佣金结算形成反向锁导致数据库死锁。

## 11. 功能开关和设置

建议继续使用以下设置：

- `distribution_enabled`：复用为“激活码推广功能”开关，关闭后不允许创建新分销批次、不建立新设备归属、不生成新佣金，并隐藏分销相关菜单。
- `distribution_default_rate_bps`：默认佣金比例，默认 `2000`，即 `20%`。
- `distribution_holding_days`：佣金观察期，默认 `7 天`。
- `distribution_min_withdraw_cents`：最低提现金额，默认 `5000`，即 `50 元`。

旧推广链接相关开关不再在设置页面展示，并在功能切换 migration 中统一设为关闭。后端不再读取该开关决定新订单归因，避免旧入口被重新开启。

关闭激活码推广功能开关后：

- 管理员不能创建新的分销激活码批次。
- 已分配的激活码仍可正常授权，但不再为新设备建立分销归属。
- 已有设备归属和历史佣金继续保留，但关闭期间的新充值不产生设备充值佣金。
- 分销者后台隐藏激活码、设备、充值和新增佣金相关菜单，用户默认首页仍可访问。

关闭开关不能删除历史归属和历史佣金。重新开启后，已有归属设备的新充值可以继续产生设备充值佣金。

## 12. 与旧推广分销的关系

旧推广链接不再作为新增分销方式。功能切换后：

- 商品购买页面不再读取或提交推广码。
- 新订单不再根据推广链接、推广码或用户邀请关系设置佣金接收人。
- 新用户注册不再建立新的永久邀请关系。
- 分销者后台不再展示推广链接和推广码入口。
- 所有新增佣金只来自归属设备的后续付费充值，来源统一为 `device_recharge`。

已有用户邀请关系、历史订单和 `referral` 来源佣金不删除，继续支持查询、观察期、提现、结算、退款取消和负向调整。第一阶段只停止旧功能产生新数据，不直接删除历史字段和表结构。

同一订单继续最多关联一条 `distribution_commissions` 记录。历史订单已经存在推广佣金时，不再补充设备充值佣金。

## 13. API 建议

分销者本人接口必须从登录令牌取得用户 ID，并校验 `distributor` 角色，不接受前端传入任意 `user_id`：

```text
GET /api/admin/me/distribution/code-batches
GET /api/admin/me/distribution/reg-codes
GET /api/admin/me/distribution/devices
GET /api/admin/me/distribution/device-recharges
GET /api/admin/me/distribution/summary
```

激活码列表、详情、复制和导出接口都必须使用令牌中的用户 ID 过滤 `reg_codes.distributor_user_id`。即使请求中伪造其他用户 ID 或批次 ID，也不能返回不属于当前用户的激活码。

管理员接口：

```text
POST /api/admin/distribution/code-batches
GET  /api/admin/distribution/code-batches
GET  /api/admin/distribution/devices
POST /api/admin/distribution/devices/{id}/attribution
GET  /api/admin/distribution/device-recharges
```

列表接口统一进行分页边界校验，并限制最大 `page_size`。

## 14. 实施顺序

1. 通过 migration 增加内置 `distributor` 角色和默认权限，并关闭旧推广链接相关设置。
2. 新增分销批次、设备充值记录和归属审计表 migration。
3. 为激活码、设备、订单和佣金表增加分销者归属字段 migration。
4. 实现管理员选择“分销者”类型用户并批量生成分销激活码。
5. 在首次绑定事务中实现设备首次归因。
6. 在后续充值事务中写入充值记录并生成佣金。
7. 接入现有退款、锁定、结算和负向调整链路。
8. 实现分销者的激活码、设备和充值记录后台。
9. 实现管理员归属查询、修正和审计功能。
10. 关闭旧推广链接、推广码和注册邀请关系的新数据入口，保留历史查询与结算。

## 15. 验收标准

- 管理员只能选择“分销者”类型用户，并生成归属于该用户的激活码批次。
- 分销者登录后只能查看自己的激活码、设备、充值和佣金数据。
- 分销者只能查看和导出 `distributor_user_id` 等于本人用户 ID 的激活码，其他激活码完全不可见。
- 终端用户不登录即可使用分销激活码首次绑定设备。
- 只有首次创建的新设备能够建立分销者归属，任何已有设备都不能补绑定。
- 换机后的新设备不继承旧设备归属，按照新设备首次激活所用激活码重新判断归属。
- 设备第一次归因后，后续使用其他来源激活码不会改变归属。
- 初始分销激活码不产生佣金。
- 付费订单充值码成功应用到归属设备后，按设置比例生成一笔佣金。
- 仅支付但尚未充值到设备的订单不产生设备佣金。
- 同一订单重复回调或重复充值不会产生多笔佣金。
- 旧推广链接、推广码和邀请关系不会再产生新佣金。
- 同一订单最多生成一笔设备充值佣金，并继续受数据库唯一约束保护。
- 后续充值退款能正确取消佣金、释放锁定或生成负向调整。
- 设备归属修正只影响未来充值，不改写历史佣金。
- 分销开关关闭时用户首页可正常访问，分销菜单隐藏。
- 用户后台不泄露购买人邮箱、IP、支付原始报文和其他分销者数据。
