# 2026-05-11 功能改动汇总

## 彩豆在线支付

- 接入彩豆支付创建订单、异步通知和同步返回。
- 支持从彩豆商户信息接口查询可用支付方式，并结合 `CAIDOU_PAY_TYPES` 过滤实际展示的支付方式。
- 支付方式改为购买时选择，不在商品卡片上提前展示。
- 支付页使用彩豆收银台跳转链接，前端不直接展示原始支付链接。
- 彩豆 `return_url` 不再停留在后端纯文本接口页，改为跳转到前端 `/pay/result` 支付结果页。

## 支付安全与订单状态

- 支付通知校验彩豆 MD5 签名、商户 PID、支付状态和订单金额。
- 支付成功处理使用数据库事务。
- 彩豆 `notify` 和用户浏览器 `return` 共用同一套幂等处理逻辑。
- 支付回调处理时对订单行加排他锁，避免同步返回和异步通知并发时重复发码。
- 订单表新增 `(provider, provider_trade_no)` 唯一索引迁移，避免同一支付平台交易号重复落库。
- 公开订单查询接口改为脱敏 DTO，不再返回 `pay_url`、`qr_code`、`url_scheme`、`reg_code_id`。

## Postgres Outbox 与 Notify

- 新增 `order_events` 事件表，作为订单状态变更 outbox。
- 支付成功发码后，在同一个数据库事务中写入 `payment.delivered` 事件。
- 同一事务内调用 `pg_notify('licensehub_order_events', '{"event_id":...}')`。
- 当前不启动后台 worker，系统仍保持单一 Web 服务运行模型。
- `order_events` 和 `NOTIFY` 先作为审计与后续扩展基础；后续需要邮件、短信、SSE/WebSocket 或外部系统通知时，再接入消费端。

## 注册码状态

- 注册码状态语义调整：
  - `未使用`：库存码，还未发给用户。
  - `已发放`：已经发给用户，但尚未绑定设备。
  - `已绑定`：用户已经在客户端激活绑定。
- 支付成功自动生成注册码时，状态直接标记为 `已发放`。
- 历史已完成订单如果关联注册码仍是 `未使用`，再次收到支付通知或回跳时会修正为 `已发放`。
- 次数类注册码首次激活后，也会标记为 `已绑定`。

## 前台购买与查询

- 首页改为全部商品总览，并按应用分标签页展示。
- `/products/{appid}` 展示指定应用下全部商品。
- 去掉重复的产品总页导航。
- 新增 `/orders/query` 订单查询页，用户可通过订单号查询支付状态和注册码。
- 新增 `/pay/result` 支付结果页，展示订单状态、商品、金额和注册码复制入口。
- 订单号和注册码都增加复制按钮。
- 支付结果、订单状态等展示使用中文文案。

## 后台管理

- 商品管理中，商品类型自动跟随所选应用类型：
  - 次数类应用只能创建次数类商品。
  - 时间类应用只能创建时间类商品。
- 应用列表增加“购买页”按钮，可跳转到该应用商品购买页。
- 应用类型修改不生效的问题已修复。
- 订单管理状态列改为多语言文案，中文支持 `待支付 / 已支付 / 已完成 / 支付失败 / 已关闭`。
- 应用创建/编辑弹窗移除当前多余字段：
  - 版本号
  - 下载地址
  - 资源地址
  - 更新信息
- 应用列表也移除版本、下载/资源链接、更新信息等多余列。

## 后续建议

- 为 `/api/orders/{order_no}` 增加二次查询凭证或查询限流，避免订单号泄露后直接查到注册码。
- 增加 Redis 限流，覆盖创建订单、订单查询、注册码校验等公开接口。
- 如需邮件、短信、SSE/WebSocket 或外部系统通知，再为 `order_events` 接入消费端；当前保持系统简洁，不默认运行后台 worker。
- 生产环境收紧 CORS，Swagger 建议通过配置关闭。
